# ProjectForge app

The mobile app of ProjectForge for iOS and Android (React Native, Expo), the successor of the Flutter app
([`projectforge-flutter`](../projectforge-flutter/README.md)). Architecture, login flow and plans:
[dev-docs/flutter-client.md](../dev-docs/flutter-client.md); conventions: [CLAUDE.md](CLAUDE.md).

## Setup (macOS)

- Node 24+ and npm on the `PATH` (`brew install node`).
- iOS: Xcode with an iOS simulator runtime (`xcodebuild -downloadPlatform iOS`), CocoaPods.
- Android: Android Studio, started once (its setup wizard installs the SDK), with an emulator of the Device Manager.

The native projects (`ios/`, `android/`) are generated by `expo prebuild` and not in git; `bin/pfApp.sh run` creates
them on its first run.

## Run

```bash
bin/pfDev.sh run 1                              # a server on :8081 (slot 1, test data), from the repo root
projectforge-app/bin/pfApp.sh run 1             # dev client in an iOS simulator, Metro on :19001, login preset to :8081
projectforge-app/bin/pfApp.sh run 1 --proxy     # the same behind the fake SSO proxy (tools/fake-sso-proxy.mjs)
projectforge-app/bin/pfApp.sh metro 1           # only Metro, for an installed dev client
projectforge-app/bin/pfApp.sh check             # tsc (app + projectforge-shared) → eslint → jest
projectforge-app/bin/pfApp.sh help              # the other helpers: sim, proxy, prebuild, build-ios, xcode, …
```

The dev client is the variant `de.projectforge.mobileapp.dev` ("PF Dev"), next to the store app on a device
(`APP_VARIANT`, see `app.config.ts`). The Android emulator reaches the Mac as `10.0.2.2` (`run --android`).

### Behind an SSO proxy

`tools/fake-sso-proxy.mjs` imitates an SSO proxy in forward auth mode (Authentik's outpost): pages without its cookie
go to a login on another host, the api gets a 401 without json, `/rsPublic/` passes. The server needs
`projectforge.app.proxyCookies=authentik_proxy_*` in its `projectforge.properties`. Options: `--ttl` (proxy session),
`--sso-ttl` (the SSO's own session: a second login without a form), `--interactive`, `--guard-public`.

## Texts

`assets/i18n/generated.<locale>.json` is generated from the server's I18nResources by `bin/pfDev.sh gen`, never edited
by hand; app only texts go into `assets/i18n/app.<locale>.json`. Keys are always written out literally:
`t('businessCard.new')`.

## Release

EAS (`eas.json`): `development` (dev client, simulator), `development-device`, `preview` (TestFlight), `production`.
The store app is `de.projectforge.mobileapp` (team `E4Q65AC7LP`), the update of the Flutter app: version 1.1.0, build
6 and up. OTA updates (EAS Update) reach only builds with the same native code (`runtimeVersion` policy
`fingerprint`). One-time portal steps (App ID, APNs keys, store listing):
[projectforge-flutter/APPLE-SETUP.md](../projectforge-flutter/APPLE-SETUP.md).
