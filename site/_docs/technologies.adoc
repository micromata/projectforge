== Supported browsers

ProjectForge runs in the current versions of all common browsers:

[cols=2*,options="header"]
|===
| Browser | Status
| Google Chrome | Supported (also used by the automated end-to-end tests).
| Microsoft Edge | Supported.
| Mozilla Firefox | Supported.
| Apple Safari | Supported.
| Microsoft Internet Explorer | Not supported.
|===

The user interface is responsive and works on desktops, tablets and smartphones.

== Requirements for the ProjectForge server

* Java 17 or newer (the code is compiled for Java 17); Micromata runs it in production on Java 21, and the
  Docker image is based on Eclipse Temurin 21.
* PostgreSQL as database for productive use. An embedded HSQLDB is available for tests and evaluation.
* Linux, macOS or Windows -- or Docker: images for amd64 and arm64 are available as `micromata/projectforge`.

How to install and run it is described in link:/docs/installation/[Installation].

== Professional architecture and CI (continuous integration)

ProjectForge is based on a modern software architecture commonly used in the industry. A role and rights
management ensures that every user can only see and use the data for which they have the required rights.

The quality and reliability of ProjectForge are based, last but not least, on automated tests: unit and
integration tests of the backend (JUnit), unit tests of the frontend (Vitest) and end-to-end tests in the
browser (Playwright). The build including the backend tests runs on GitHub Actions for every push and pull request to the development branch.

== Rapid application development

ProjectForge is designed for developing new functionality fast:

* Write the entity in Kotlin and define its database mapping and search index with annotations (JPA,
  Hibernate Search).
* Derive the data access object from the base class: access checks, history and persistence are inherited.
* Derive the REST service from the base class: list, filters, favorites, history, create, update and
  delete are inherited.
* Declare the list and edit page in the Next.js frontend: field types, lengths, mandatory fields and labels
  are generated from the entity.

Every entity gets:

* Secure access checking.
* Full text search.
* A history of every user's modifications.
* Full database support with versioned migrations.

Details are described in link:/docs/development/[Development].
